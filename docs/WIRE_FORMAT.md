# Wire Format Specification

This document summarizes the subset of the D-Bus binary wire format implemented by `tinywasm/dbus`.

## Byte Order & Alignment

- Little-endian (`'l'`) is used for all messages generated by this client.
- Every type is aligned to its own natural boundary (padding bytes are set to `0x00`).

## Type Set & Encoding Rules

| D-Bus type | Signature | Go type | Alignment | Encoding |
|---|---|---|---|---|
| BYTE | `y` | `byte` | 1 | 1 byte |
| BOOLEAN | `b` | `bool` | 4 | uint32, 0 or 1 |
| UINT32 | `u` | `uint32` | 4 | uint32 (little-endian) |
| STRING | `s` | `string` | 4 | uint32 length (bytes) + UTF-8 bytes + NUL byte |
| OBJECT_PATH | `o` | `ObjectPath` | 4 | same as STRING |
| SIGNATURE | `g` | `string` / `Signature` | 1 | 1 byte length + ASCII bytes + NUL byte |
| ARRAY | `a<T>` | `[]T` | 4 | uint32 length in bytes (excluding padding to T), alignment padding to T, elements |
| STRUCT | `(...)` | struct | 8 | fields in order, each aligned to field boundary |
| VARIANT | `v` | `Variant` | 1 | SIGNATURE + encoded value |
| DICT_ENTRY | `{KV}` | `map[K]V` | 8 | Key then Value; always aligned inside an array |

## Message Header Layout

```
Byte 0:      'l' (Little-endian byte order)
Byte 1:      Message Type (1=METHOD_CALL, 2=METHOD_RETURN, 3=ERROR, 4=SIGNAL)
Byte 2:      Flags (0x1=NO_REPLY_EXPECTED, 0x2=NO_AUTO_START, 0x4=ALLOW_INTERACTIVE_AUTHORIZATION)
Byte 3:      Protocol Version (1)
Bytes 4-7:   Body length in bytes (uint32)
Bytes 8-11:  Serial number (uint32)
Bytes 12..:  Header fields array: a(yv)
Padding:     Pad to 8-byte boundary
Body:        Encoded argument list
```

## Header Field Codes

1. `PATH` (`o`): Object path
2. `INTERFACE` (`s`): Interface name
3. `MEMBER` (`s`): Method or signal name
4. `ERROR_NAME` (`s`): D-Bus error name
5. `REPLY_SERIAL` (`u`): Serial number of method call being replied to
6. `DESTINATION` (`s`): Bus name of destination recipient
7. `SENDER` (`s`): Unique bus name of sender
8. `SIGNATURE` (`g`): Signature of body payload
